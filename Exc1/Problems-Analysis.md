# Проектная работа спринта 11

## Кейс компании «Будущее 2.0».

### Задание 1

#### Проблемные места
 - Использование устаревших технологий (Microsoft SQL 2008 ... etc).
 - Все данные сосредоточены в DWH, что является слабым местом для развития проекта, для добавления новых доменов и масштабирования.
 - Используется устаревшая версии Apache Camel - так же является сложной технологией для интеграций.
 - Интерфейс Power Builder не масштабируется под новые требования бизнеса и является устаревшим решением для взаимодействия с данными.
 - Все данные из различных доменов лежат в одном месте, что создаёт риск безопасности.
 - Большие объёмы данных (сотни терабайт) и большое количество трансформации, что замедляет время выхода на рынок (TtM).
 - Отсутствие видения архитектурного планирования.

#### Must Have
- Необходимо перевести DWH на более современные технологии. Это позволит улучшить производительность и надежность системы, а также упростить управление большими объемами данных.

#### Should Have
- Необходимо упростить процессы интеграции новых доменов.

#### Could Have
- Автоматизация обновления витрины данных.

#### Would Like
- Документация. Можно писать документацию только для новых сервисов. Все что касается legacy можно будет документировать в будующих этапах улучшеиня архитектуры
